  1. O que são operações de “Commit”, “Push” e “Pop” efectuadas num repositório?

    O Commit permite guardar as alterações feitas no repositório local, criando um registo que podemos consultar posteriormente para perceber o que foi alterado.

    O Push é utilizado para enviar os commits do nosso repositório local para o repositório remoto, por exemplo, no GitHub ou GitLab.

    Quanto ao Pop, no Git temos o comando git stash pop, que permite recuperar alterações que tínhamos guardado temporariamente com o git stash, retirando-as da lista de alterações guardadas, caso a aplicação seja bem-sucedida.

    Existe também o Pull, que utilizamos para trazer as alterações do repositório remoto e integrá-las na nossa branch local. Não se deve confundir Pull com Pop.

  2. Quais são as vantagens de usar Branches num repositório Git?

    As branches permitem trabalhar em diferentes funcionalidades ou correcções sem interferir directamente com o código principal do projecto.

    Por exemplo, quando estamos a desenvolver uma nova funcionalidade, podemos criar uma branch específica para esse trabalho, fazer os testes e, quando estiver tudo validado, integrar as alterações na branch principal.

    Entre as principais vantagens estão:

    • Separar o desenvolvimento de funcionalidades e correcções.
    • Facilitar o trabalho de vários programadores no mesmo projecto.
    • Testar alterações antes de as integrar na branch principal.

  3. Nos merges de conteúdos resultantes de um “Pop” podem surgir conflitos. Em que consistem e como podem ser resolvidos?

    Os conflitos acontecem quando o Git encontra alterações que não consegue conciliar automaticamente. Isto pode acontecer, por exemplo, quando duas pessoas alteram a mesma parte de um ficheiro ou quando recuperamos alterações guardadas com git stash pop que entram em conflito com as alterações actuais.

    Para resolver um conflito, podemos seguir estes passos:

    1. Identificar os ficheiros com conflito.
    2. Comparar as versões e decidir que conteúdo manter ou como combinar as alterações.
    3. Editar e guardar os ficheiros, removendo as marcações de conflito.
    4. Usar git add para indicar que os conflitos foram resolvidos.

    No VS Code, podemos visualizar as diferenças e resolver os conflitos com o editor. É importante verificar o resultado antes de continuar o trabalho.

  4. “Clone” e “Fork” são formas diferentes de replicar um repositório Git. Quais são as diferenças entre eles?

    O Clone permite criar uma cópia de um repositório remoto no nosso computador. É o que fazemos quando queremos começar a trabalhar localmente num projecto que está no GitHub ou GitLab.

    O Fork, por sua vez, cria uma cópia de um repositório na nossa própria conta da plataforma, permitindo desenvolver alterações de forma independente do projecto original.

    A diferença principal é esta: o Clone cria uma cópia local, enquanto o Fork cria outro repositório na plataforma. Depois de fazer um Fork, também podemos cloná-lo para o nosso computador.

    O Fork é bastante utilizado quando queremos contribuir para projectos de outras pessoas sem termos permissão para alterar directamente o repositório original.
